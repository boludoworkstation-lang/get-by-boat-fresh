# Get By Boat — iPhone app

A Flutter iOS app that uses Get By Boat's existing Supabase project. This is the
**first iPhone beta**, not yet an App Store submission.

## What's included

- Five-tab iPhone interface: Explore, Saved, Bookings, Messages, Account
- Native boat discovery, search, boat-type chips, photos and detail screens
- Saved boats synced to the existing `favourites` table
- Existing customer and owner bookings (read-only) with their real status
- Booking conversations with read/send messages, using existing RLS policies
- Email/password login, registration, password reset and sign out
- Secure handoff to the existing website for booking requests, profile and document updates
- Brand-matched wave icon generation for iOS

No new database schema, permissions, prices or live website configuration are changed.
The app only embeds a Supabase *publishable* key, never a secret/service-role key.

## Generate and run the iPhone project on your Mac

1. Install [Xcode](https://developer.apple.com/xcode/) and
   [Flutter](https://docs.flutter.dev/get-started/install/macos/mobile-ios).
2. Clone the repository, then in macOS Terminal:

   ```sh
   cd get-by-boat-fresh/mobile
   flutter doctor -v
   flutter create --platforms=ios --org net.getbyboat .
   flutter pub get
   python3 tool/generate_ios_icon.py
   flutter run
   ```

3. Open `ios/Runner.xcworkspace` in Xcode and select your Apple Developer team
   under **Runner → Signing & Capabilities**.
4. Set a **unique Bundle Identifier** under **Runner → General** (for example,
   `net.getbyboat.app`, if available). Keep this identifier stable.
5. Test on a physical iPhone and on the simulator.

The iOS Runner project is generated by the Flutter CLI and is intentionally
not stored in this branch. CI creates it and checks the simulator build.
Commit the generated `ios/` project once your signing identity and deployment
settings are confirmed. Do not commit signing certificates or API secrets.

## How to build for submission

After setting up your developer account, app identifier, signing and production
metadata:

```sh
cd get-by-boat-fresh/mobile
flutter build ipa
```

Use Xcode Organizer or App Store Connect to upload the archive.

## App Store launch blockers

Before submitting for Apple review, finish and verify:

- **Account deletion:** Apple requires a discoverable in-app process to initiate
  deletion for apps offering account creation. This requires a secure backend
  deletion process, including legal retention decisions for paid bookings and
  identity documents. It is **not implemented** in this beta.
- **Authentication and booking:** Test login/registration/reset on physical
  devices; verify account and booking website handoffs. Native booking requests,
  payment and document uploads still use the website.
- **Messages and owner permissions:** Test all existing RLS and booking states
  using real customer and owner test accounts. The beta includes no automatic
  push notifications or moderation/report UI.
- **App icon and launch assets:** Review the generated icon on real devices,
  and add any additional launch artwork required by design.
- **App Store details:** Privacy policy, support URL, screenshots, description,
  age rating, privacy labels and a working review/demo account.
- **Payments and policies:** Verify the live payment flow, account deletion,
  refund/cancellation policy, and data handling before taking real payments.
- **Signing:** Apple Developer Program membership, Xcode distribution signing
  and App Store Connect access.

## Notes for maintainers

- `lib/data.dart` reads published boats and user-visible bookings and messages.
  It must respect Supabase RLS; never add a service-role key to the mobile app.
- The booking action intentionally opens the authoritative website checkout.
  Do not create bookings by calculating fees on the device.
- App navigation handles returning from detail and chat screens with a native
  back arrow.
- This branch does not publish or redeploy the production website.
